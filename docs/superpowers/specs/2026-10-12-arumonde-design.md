# あるもんで — 設計

手持ちの調味料・食材を登録しておき、それを元に「今日なに作る？」を外部サービス（AI・レシピサイト）に投げるためのツール。
アプリ自身はレシピを持たない。**在庫の管理**と**いい質問文を作って渡すこと**に専念する。

## 方針

- 検索は外部に丸投げ。質問文入りのURLを開く（APIキー・サーバー不要）。
- Vite＋素のJS の静的サイト、データは localStorage、PWA でホーム画面に置ける。port 5770。
- やらない: ログイン/同期、期限管理、写真読み取り、アプリ内レシピ表示。

## 画面（下部タブ3つ）

### 棚
- 登録済みの品目を区分（調味料 / 食材）× 棚（さしすせそ・洋風・中華/韓国・スパイス・油/粉・肉・魚介・野菜・きのこ・卵/乳/豆腐・乾物/缶詰・主食 等）で表示。
- 長押し（またはスワイプ）で「切らした」にする。灰色で残り、タップで復活。完全削除はメニューから。

### 追加
- プリセット約120品目を棚ごとにチップ表示。タップで登録/解除（登録済みは塗り表示）。
- 上部に文字検索。該当がなければ「◯◯を追加」で自由入力登録（区分・棚を選ぶ）。

### 探す
- 在庫ありの**食材**をチップで並べ、タップで今日使うものを選ぶ。選択中をもう一度タップで ★（必ず使う）、さらにタップで解除。★は最大2個。
- 条件チップ: 人数（1/2/3/4人分）、時間（15分以内/30分以内/こだわらない）、気分（さっぱり/がっつり/あったか/ヘルシー、複数可）。
- 質問文プレビュー（textarea、手で書き換え可。条件を変えると再生成し、手編集は破棄されることを明示）。
- 送り先ボタン:
  - AI（質問文を渡す）: ChatGPT `https://chatgpt.com/?q=`、Claude `https://claude.ai/new?q=`、Perplexity `https://www.perplexity.ai/search?q=`
  - Gemini: URL受け渡し不可 → クリップボードにコピーしてから `https://gemini.google.com/app` を開き、トーストで「貼り付けてください」。
  - レシピサイト（キーワードを渡す）: クックパッド `https://cookpad.com/jp/search/<kw>`、Google `https://www.google.com/search?q=<kw>+レシピ`
  - URLが有効かは実装時に実ブラウザで確認する。

## 質問文（AI向け）

組み立て順:
1. 主題: ★あり →「{★}を必ず使って、」／なし → なし
2. 条件: 「{n}人分」「{時間}で作れる」「{気分}な」を自然に連結
3. 依頼: 「晩ごはんのレシピを3案ください。」（献立種別は固定。YAGNI）
4. 「他に使ってよい食材：…」（選択中の★以外）
5. 「使ってよい調味料：…」（在庫ありの調味料全部）
6. 固定の締め: 「これ以外の材料を使う場合は『要買い足し』と明記してください。各案に材料と分量、手順を簡潔に。」

境界:
- 食材が1つも選ばれていない → 「手持ちの調味料だけで作れるもの、または少しの買い足しで作れるもの」を依頼する文にする。
- 調味料0 → 5行目を省く。
- URL長: エンコード後 6000 文字を超えるとき、調味料リストを末尾から削って「ほか基本調味料」で締める。それでも超えるなら食材リストも同様に削る。★と条件は削らない。

## キーワード（レシピサイト向け）
- ★があれば★のみ。なければ選択中の食材の先頭3つ。気分は付けない。空なら送り先ボタンを無効化。

## データ

```js
// localStorage key: "arumonde:v1"
{
  items: [{ id, name, kind: "seasoning"|"ingredient", shelf, outOfStock: false, addedAt }],
  prefs: { servings: 2, time: null, moods: [] }
}
```
- 名前の正規化（重複判定用）: 全角/半角・ひらがな/カタカナ統一＋同義語表（しょうゆ=醤油=しょう油、さとう=砂糖 等）。プリセットは正規化名で一意。
- 読み込み時に不正データを防御（壊れていたら空で起動し、壊れた生データは `arumonde:v1:broken` に退避）。

## 構成

- `src/lib/`（純粋関数・Vitest）
  - `presets.js` 品目データ（name, kind, shelf, aliases）
  - `normalize.js` 名前正規化
  - `pantry.js` add / toggleOut / remove / 重複判定 / 在庫ありの絞り込み
  - `prompt.js` buildPrompt(state, selection, prefs) / buildKeywords
  - `handoff.js` 送り先定義と URL 生成、長さ制御
  - `storage.js` load / save / 防御
- `src/ui/` 3画面の描画とイベント。`src/main.js` で配線、`window.__app` を公開。
- PWA: manifest＋最小 service worker（静的アセットのキャッシュ）。

## テスト
- lib をすべて単体テスト。prompt は境界の総当たり（★0/1/2 × 食材0/1/多 × 調味料0/多 × 条件の有無）で、文が崩れない・必須要素が入る・URL長上限を守ることを確認する。
- UI は window.__app 経由でブラウザ pane から検証する。送り先URLが実際に質問文入りで開くかを目視で確認する。
